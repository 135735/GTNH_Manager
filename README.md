# Machine Radar 0.11（单机）

GTNH 2.9 附属：扫描附近每一台 GT 机器（多方块 / 单方块），把**整台机器的真实结构**、
舱室、状态、配方信息叠在世界里；右侧面板展开焦点机器细节，机器图标标出"这是什么"。
**L** 打开工厂列表（分组 / 多选 / 批量开关机 / 统计 / 详情），**N** 2D 多图层机器地图，
**H** 效率心电图。

多方块的结构方块不是猜的：**直接借 GT 自己的结构校验**，通过 StructureLib 的遍历事件
把每个结构单元的绝对坐标收下来。原理与源码引用见 [docs/STRUCTURE.md](docs/STRUCTURE.md)，
后续规划见 [docs/ROADMAP.md](docs/ROADMAP.md)，换机器开发见 [docs/DEVELOP.md](docs/DEVELOP.md)。

## 装

```powershell
Copy-Item 'machine-radar/dist/machineradar-0.11.0.jar' `
  'E:\gtnh29\GTNH-2.9.0-RC\.minecraft\versions\GT New Horizons 2.9.0-RC-2\mods\'
```

单机 integrated server 与客户端同进程，客户端一份即可。

## 按键

| 键 | 动作 |
|---|---|
| **K** | 开关雷达 |
| **Ctrl+K** | 图层循环：全部 → 仅多方块 → 仅单方块（写进配置） |
| **Shift+K** | 导出 dump（`config/machineradar/dump-*.json`） |
| **L** | 打开工厂列表（分组 / 搜索 / 排序 / 详情 / 追踪） |
| **N** | 打开 2D 多图层机器地图 |
| **H** | 效率心电图（准星机器 / 追踪机器） |
| **M** | 游戏内设置界面 |
| **V** | 3D 选区：设角点1 → 设角点2 → 选区归组界面（**Ctrl+V** 取消） |
| **G** | 分组图层开/关：只看分区区域 + 大标签，不画机器本体（写进配置） |

**框选杖（物品）**：`雷达框选杖`，默认合成 `木棍 + 红石 + 金锭`（无序合成）。
拿着它右键方块就设角点（右键会被工具吃掉，不会顺手开机器界面）：
第一次角点1、第二次角点2 并自动开归组界面；右键空气重新打开归组界面；潜行+右键清除选区。
它和 **V** 键用的是同一套选区状态，两个入口可以混用。

按键可在「选项 → 控制 → Machine Radar」里改。

## 显示

- **外壳填色**：只生成**紧贴外部空气**的面（包围盒外泛洪判定），所以机器中空的内壁不会
  被染色；渲染时开深度测试 + 背面剔除 + 关深度写入，只留玩家这侧最外层的一层颜色。
  近处有填色，超过 `fillRadius` 后淡出只留线框；`overlayXray` 打开才会穿墙（默认关）。
- **线框（外轮廓）**：不再画"每个方块的折边"，而是按当前视角算**轮廓边**——两个相邻外表面
  一个朝你、一个背你时才是轮廓；共面相邻的格子线在网格阶段就丢掉了。复杂结构也只是一圈
  外轮廓，不会糊。
- **遮挡剔除**：线框绘制前先做一次**深度预写**（只写深度不写颜色），再按深度测试画轮廓。
  凹形结构/被前面机器挡住的后方轮廓会被正确剔除，不再出现"背面杂线"。
  设置里的「线框 X 光」（`wireframeXray`，默认关）会跳过预写并让焦点轮廓穿墙——
  需要隔墙找机器时才开。
- **线框范围**：设置里的「线框只画点选机器」（`wireframeFocusOnly`）：
  - 开 = 只画准星点选的那一台（白色加粗）；
  - 关（默认）= 全部机器都画，但**有区分**：非焦点是状态色细线、开深度测试（被墙挡住就不画），
    焦点白色加粗。
- **焦点**（射线打中整机 AABB 的最近一台）：白色加粗轮廓 + 外壳更亮 + 控制器穿墙脉冲；
  舱室全显示，并在世界里标出每个舱室的朝向（北/南/东/西/上/下）。
- **副焦点**：准星方向上、被焦点机器挡在后面的其它主控，会以较小的色块提示（`secondaryConeDegrees`，0=关闭），
  不会抢焦点信息。
- **非焦点舱室**：默认不显示（`hatchFocusOnly`）；关掉该开关后，只有走到
  `hatchNearRadius` 内才显示淡化的小点。
- **机器图标**：把机器本身的物品形态渲染成屏幕恒定大小的图标，悬浮在机器上方，
  一眼看出"这是工业高炉还是焦炉"。超过 `iconRadius` 不显示。
- **单方块**：只显示电压色小点 + 图标；舱室方块不再混进单方块列表（它们属于多方块）。
- **距离衰减**：`d / 机器半径` 的 1.7 次幂淡出，下限 `fadeFloor`；`maxDistance` 外不显示。

## 工厂列表（L）

按 **L**（或 `/mradar list`）打开，数据来自同一次服务端扫描快照：

- **多选**：单击单选；**Ctrl+单击**切换单个；**Shift+单击**区间连选；**Ctrl+A** 全选；
  ↑/↓ 选择（按住 Shift 扩展区间）。
- **左栏分组**：全部 / 未分组 / 自定义分区（带颜色、图标与 `在线/总数`）；
  底部「＋ 新建分组」；**右键分组**改名 / 删除 / **用选中机器的物品图标作为分组图标** /
  **设为当前选区** / **清除区域**。
- **归组**：选中（可多台）后点「加入组…」，在弹窗里**直接选**「＋ 新建分组」或任一已有分组，
  一步完成（不用先到左栏选组）；「＋ 新建分组」按钮也会把**当前选中的全部机器**一起建进新组。
  也可以把列表行**直接拖到左栏分组**上，拖到「未分组」就是移出。单方块机器和多方块一样可以分组。
- **远程开关机**：选中一台或多台后点「开关」（或「关闭/开启」），通过
  `enableWorking()/disableWorking()`（软锤语义）在服务端线程执行，不会破坏结构；
  只支持单机 integrated server。停机机器在列表/地图里变灰、状态显示「已停机」。
- **统计开关**（底部第二排）：
  - 「统计：分组 / 全局」——只统计已分组（或当前选中的组）的机器，或统计全局；
  - 「分帧：开 / 关」——全局统计每隔 2.5 秒启动，开启分帧时每帧只处理 96 台，
    避免一次性遍历造成卡顿；分组统计是 1 秒一次的全量；
  - 「调试：开 / 关」——单独一行显示统计耗时、选中数量、分帧进度、选区尺寸；
  - 「区域：关 / 分组框 / 区块预览」——见下面的区域预览；
  - 「分析：关 / 全局 / 分组」——打开右侧分析面板（见下）。
- **分析面板（全局 / 分组预览 + 效率图，可开关）**：
  - 打开时**页面加宽**并让出右侧一列，列表 / 详情 / 分析三栏并排，不会盖住下层；
  - 顶部两个按钮：「窗口：秒 / 分钟 / 小时」切换统计口径，「范围：全局 / 分组」切换全局或左栏选中组；
  - 中间是效率曲线（最近 2 分钟，1 秒/点）：绿线 = 在跑配方的机器占比，蓝柱 = 合计耗电；
  - 下面给台数 / 运行 / 待机 / 未成型、窗口运行率、合计 EU/t 与产出；
  - 「全局」范围还会列出**每个分组的预览行**（在线/总数、运行率、EU/t），这就是打组预览；
  - 选「分组」范围时列出该组成员及各自 EU/t。
- **滚动**：滚轮在机器列表上翻列表、在左栏分组上翻分组；两处都有**可拖动的滑块**。
- **搜索**：名字 / `getMetaName()` / 电压 / MTE id / 「多方块」「单方块」；
- **排序**：距离 / 名称 / 电压 / 状态；
- **图层**：全部 / 仅多方块 / 仅单方块，和世界里的 Ctrl+K 同步写配置；
- **列表行**：分组色条（或分组图标）+ 状态点 + 机器图标 + 名字 + 电压 + 状态 + 舱室数 + 距离；
- **右栏详情**：坐标/维度/距离、电压、分组、结构方块数（精确/未知）、进度条与配方耗时、
  耗电与能源仓上限、产出速率、维护缺失、**输入/输出总线与仓的计数**（物品数量+槽位、
  流体 mB/容量）、**近 1 分钟历史**（运行占比 / 平均耗电 / 产出，附迷你柱状图）、舱室分类统计；
- **追踪**：双击一行或按回车，关闭界面后世界里白色脉冲框 15 秒；
- **心电图 / 地图**：底部按钮或 H / N（「心电图」在没有选中单机时会打开左栏分组的聚合视图）。

Esc 关闭，Ctrl+F 回到搜索框。列表只显示当前维度；打开列表会自动把雷达设为开启。

## 区域预览（分组 AABB / 区块预览）

底部「区域」按钮循环三种模式（写进 `groupPreviewMode`）：

| 模式 | 世界内 | 地图 / 列表 |
|---|---|---|
| 关 | 不画 | 不画 |
| 分组框 | 每个分组一个整体 AABB 线框 + 组名/台数标签 | 地图画分组矩形；列表空选时列出各组台数 |
| 区块预览 | AABB 按 16 格区块对齐（基础占位） | 同上，并显示 `A×B 区块` 统计 |

这是"基于分组机器做统筹数据"的第一版：目前给的是在线台数、整体范围和区块数量，
后续会往区域产量/能耗汇总、边界编辑继续加。分组的范围优先用**显式区域**（3D 框选定出来的），
没有区域才用成员机器 bbox 的并集。

## 3D 选区（框选杖 / V）
目标是「框一片地方，直接把里面的机器归组」，不再靠机器包围盒猜范围。

1. 拿着**雷达框选杖**右键一个角点方块（或按 **V**）→ 记角点 1（聊天栏和屏幕底部都会显示坐标）；
2. 再右键对角（或再按 **V**）→ 记角点 2，世界里出现青色线框 + 白色角点，并自动打开**选区归组**；
3. 归组界面里点「＋ 新建分组（N 台）」或任一已有分组 → 选区内**与框相交**的整台机器一次性处理：
   - 模式「加入成员」（默认）：只加不删；
   - 模式「替换成员」：清空该组原有成员，只保留框内机器（「替换一个现有分组」）；
   - 「记录为分组区域」打开时，这个框会存成该分组的显式区域（写进 `groups-<世界>.json`）；
4. **Ctrl+V** 或 潜行+右键 取消选区；已经框完后按 **V** / 右键空气会重新打开归组界面。

- 相交判定：多方块按整机结构 bbox（没有结构数据时用控制器那一格），单方块按它自己那一格——
  控制器不在框里、机器伸进框里也算命中。
- 有显式区域的分组：世界里的区域预览、2D 地图、列表详情都直接用区域框，不再随成员机器增减而变形；
  没有区域的分组仍退回「成员 bbox 并集」。
- 区域按世界、按维度各存一份；换维度框选会自动重开一个新框，跨维度的旧框不会被误用。
- 列表底部的「选区」按钮可以直接启动这个工具（关掉列表回到世界）。

## 分组图层（G）

按 **G** 切换「分组图层」：世界里**只画分组区域框 + 放大的组名标签**，不画任何机器本体
（填色 / 线框 / 图标 / 舱室全停）。用来"按分区看整体"，不会和机器线框糊在一起。

- 区域框用分组颜色；标签按距离自动放大（0.028~0.75），显示 `组名 · N台（M运行）`；
- 和「区域：分组框」的区别：后者是在**机器图层上叠加**区域框，分组图层是整套视图切换；
- 开关写进 `showGroupLayer`，重进游戏保持；
- 没有显式区域的分组按成员 bbox 画，有显式区域的按区域画（和列表/地图一致）。

## 存储机器与当前配方

- **存储机器**：量子箱（`MTEQuantumChest`）/ 量子缸（`MTEQuantumTank`）会读出存储对象、
  数量与容量，详情面板显示 `存储 物品 ×数量 / 容量` 或 `存储 流体 数量 mB / 容量`；
- **当前配方**：单方块机器通过反射读 GT 的 `mLastRecipe`，详情面板显示
  `配方 入 A×2 + B×1` / `出 C×1 · 3.5s · 32 EU/t`；
- 多方块没有 `mLastRecipe`（GT 把配方存在处理逻辑里），只能显示**输出 + 时长 + EU**，输入未知；
- 这些数据同时喂给下面的分组台账；读不到配方时退回"第一个输出 + 时长"的估算。

## 分组产能台账（资源效率，类异星工厂）

`ProductionLedger` 在客户端每秒采样一次，把"组内正在跑的配方"按运行时间积分到**资源**上：

- 每种资源（物品 `i:` / 流体 `f:`）记录**产出**和**消耗**，各自有 120 个秒桶（2 分钟）
  和 60 个分钟桶（1 小时）；
- 内存固定：每资源 4 个 long 数组，单组最多 96 种资源；桶按「时间 % 长度」复用，写入前清槽；
- 成本 ≈ 机器数 × 几次乘加 / 秒，和 `MachineHistory` 同一量级，不扫世界、不做字符串拼接；
- 组内统计：窗口平均功率（EU/t）、窗口完成配方数、累计完成配方数。

**效率图（H / 列表「心电图」）的分组视图**已经接上：

- 右侧「资源」列表按净产出排序，行尾是该窗口的净产出（绿=正、红=负）；
- 点某个资源 → 主图切成该资源的**产出（绿线）/ 消耗（红线）**双曲线；
- 「窗口：2分 / 15分 / 1时」切换，秒级窗口用秒桶，长窗口用分钟桶；
- 点最上面的「整组活动曲线」回到原来的"运行占比 + 合计耗电"图；
- 列表的「分析 · 分组」面板也会显示该组资源净产出 Top 8。

> 数值是**估算**：按配方输出 × 运行时间 / 配方时长积分，不是 GT 输出总线的真实计数；
> 对效率/产线比较够用，但不要拿去对仓库账。

## 机器地图（N，多图层版）

`GuiMachineMap`：以打开时的玩家位置为中心，2D 俯视。底部两排按钮就是图层开关：

- **多方块**：画整机 **XZ 足迹**（不是只画主控点）+ 主控点，足迹填充/边框用分组色或状态色；
- **单方块**：画小点（分组色优先，否则电压色），有配方运行时中心加白点；
- **电网**：所有能源仓/动力仓画成点（颜色=电压等级），并从主控连线到舱室；
- **物流**：物品输入/输出总线点 + 连线；
- **流体**：流体输入/输出仓点 + 连线；
- **层：全部 / ±8 / ±16**：按主控 Y 过滤，专门处理上下堆叠的机器；
- 悬停显示名字、Y、XZ、状态、进度、同位置堆叠数量；单击选中、双击追踪；
- 滚轮缩放（0.4~6 px/格），网格 16 格起、缩小时自动加倍；
- **绘制顺序按 Y 从低到高**（单轴排序，不做等距/透视）：高的机器盖在低的上面；
  同 XZ 位置的堆叠机器悬停会提示“同位置堆叠 N 台”，配合层筛选分开看。

> 这一版的电网/物流/流体图层画的是**机器侧舱室端口**（能源仓、总线、流体仓）及其到主控的
> 内连线；世界里的 GT 电缆/管道的拓扑还没有扫（需要额外扫描非机器 TE 并做连通性），
> 作为下一轮迭代。

## 效率心电图（H）

`GuiEfficiency`：把 `MachineHistory` 最近 2 分钟的采样画成滚动曲线。

- 绿线：每秒“是否在跑配方”的心跳（运行=上沿，停机=底部细线）；
- 蓝色柱：当时耗电（绝对值归一化）；
- 橙色细线：配方进度 0~100%（有进度时）；
- 顶部：机器名/分组/状态/Y，运行占比、平均 EU/t、平均产出、采样数；
- 入口：机器列表选中后点「心电图」、地图选中后点「心电图」，或世界里对准机器按 **H**
  （优先准星机器，其次追踪机器）。
- **分组视图**：列表左栏选中一个分组、不选单机时点「心电图」，看的是整组：
  绿线 = 那一刻「在跑配方的机器占比」（0~1），蓝柱 = 该组当时合计耗电；
  顶部给在线台数、运行占比、合计 EU/t、合计产出、有采样的台数。
  界面里用「看分组 / 看单机」随时切换；分组聚合按成员采样末端对齐后逐点求和
  （`MachineHistory.trace`）。
- **分组视图的右侧资源台账**（0.11）：列出该组产线在窗口内的产出/消耗（净产出排序），
  点资源把主图切到「产出 vs 消耗」双曲线；「窗口：2分 / 15分 / 1时」切换，
  数据来自 `ProductionLedger`（类异星工厂的产量图，详见上面的「分组产能台账」）。
- 界面每帧重读历史缓冲，开着的时候曲线是实时滚动的。
- **已并入工厂列表**：列表底部「分析：全局 / 分组」打开右侧分析面板，同一套曲线在面板里看；
  独立界面（H）仍然保留，适合全屏看单台或单组。

## 窗口统计（秒 / 分钟 / 小时）

列表分析面板顶部的「窗口」按钮切换统计口径：

| 窗口 | 含义 | 数据来源 |
|---|---|---|
| 秒 | 最新一条采样（1 秒粒度，≈ 实时） | 环形缓冲最后一条 |
| 分钟 | 最近约 1 分钟的指数滑动平均 | 每台机器 6 个 EMA 字段（时间常数 60s） |
| 小时 | 最近约 1 小时的指数滑动平均 | 同上（时间常数 3600s） |

- EMA 跟着每秒采样更新，所以「小时」不需要存 3600 个点：每台机器只多 6 个 double；
- 曲线本身仍然是**最近 2 分钟、1 秒/点**（不随窗口变化），窗口只影响面板上的运行率 / 合计 EU/t / 产出；
- 刚进游戏时「小时」还没攒够数据，数值会向当前值快速收敛，属于正常现象。

## 后台历史数据

`MachineHistory` 在客户端每秒给快照里每台机器记一条（时间 / EU / 产出 / 配方进度 / 是否运行），
保留最近 2 分钟（120 条）。列表详情、效率心电图都读这份环形缓冲；后续的产量曲线、
利用率统计也用它。只在客户端内存里，不写盘、不多人同步。

## 性能（0.6.1 实测）

本机 JDK 25 微基准，只看数量级：

| 项目 | 实测（1000 台，每台按 400 条边算） | 折算 |
|---|---|---|
| 历史采样（建 key + HashMap + 写 5 个数组） | **33.8 µs / 秒** | ≈0.003% 单核 |
| 只做 HashMap 查找（key 预生成） | 7.4 µs / 秒 | — |
| 外轮廓逐帧（100 台 × 400 边） | **72 µs / 帧** | ≈4.3 ms/s @60fps（0.4%） |
| 世界名 `replaceAll` 清洗 | 296 ns/次（手工 22 ns） | 0.6.1 已不在每帧调用 |

- 历史是**每秒一次**的 O(机器数) 遍历：1000 台约 3 MB 内存（4096 台上限约 12 MB），
  每秒约 1000 个短命 String（~50 KB/s），GC 无压力；
- 真正的每帧开销是外轮廓：全量模式默认只算**最近 96 台**（`wireframeMaxMachines`，
  设置里的「线框机器数」，0=不限）；只看准星那台就开「线框只画点选机器」，
  此时每帧只算 1 台；
- 分组查找每帧会被列表/地图调用很多次：0.6.1 起走 `World` 引用快速路径，
  不再每帧取世界名 + 正则清洗；
- 地图图层是 2D `drawRect`/线段，每帧 O(机器数 + 舱室数)；心电图只在打开时画 120 个点，
  两者都比世界内的外轮廓便宜；
- 线框遮挡剔除会多一遍"只写深度"的面片 pass（和填色同量级，受 `wireframeMaxMachines` 限制）；
  不想付这笔钱就开「线框只画点选机器」；
- 工厂页统计不再每帧全量遍历：只统计分组时 1 秒一次，全局 2.5 秒启动一次并可分帧（每帧 96 台）；
- 服务端每秒一次的扫描（读 MTE / 结构校验）仍然是主要开销，比历史采样高几个数量级，
  和这里讨论的客户端采样无关。

## 已知限制

- **只支持单机**（服务端扫描 → 同进程快照）。多人需要网络包。
- 不经过 StructureLib 校验的第三方多方块（部分 GT++ legacy 机器）拿不到精确集合，退化为控制器标记。
- 结构缓存 120 秒，拆改机器后最多 2 分钟刷新，`/mradar rescan` 可立即刷新。
- 舱室方块本身不再作为"单方块机器"显示（它们属于多方块）。
- 图标只对能在物品栏里找到形态的机器有效；极少数 MTE 的 `getStackForm(1)` 返回 null。
- 工厂列表只列当前维度；状态最多落后一个 `refreshTicks`（默认 1 秒）。
- 追踪高亮 15 秒后自动消失；切换雷达关闭也会清掉追踪。
- 分组是客户端数据，按存档名存 `config/machineradar/groups-<世界名>.json`；
  换存档是另一套分组。
- 历史采样只在客户端内存（最近 2 分钟），退出游戏就没了；多人不会同步。
- 「分钟 / 小时」窗口是**指数滑动平均**（EMA，时间常数 60s / 3600s），不是严格的整段历史平均：
  刚进游戏或长时间暂停后需要一点时间收敛；秒窗口才是精确的最新采样。
- 全量线框默认只给最近 96 台算轮廓（`wireframeMaxMachines`），再远的机器没有线框；
  想要全部就把它调大或设 0。
- 地图的电网/物流/流体图层是**舱室端口**，不是世界里的电缆/管道拓扑；后者需要扫描非机器 TE。
- 地图是 2D 俯视 + Y 单轴排序，不做透视/等距；同位置堆叠用「层」筛选和悬停提示区分。
- **远程开关机只在单机**（客户端→同进程服务端动作队列）；多人需要服务端网络包。
- 分组图标存的是「物品注册名 + meta」，不带 NBT；极少数需要 NBT 区分的物品图标可能显示成默认形态。
- 区域/区块预览：分组的范围要么是显式区域（3D 框选存的），要么是成员 bbox 的并集；
  区域是**矩形方块框**，不支持球形/多面体，也不会自动把以后新出现的机器加进组。
  区域按世界 + 维度存，换维度要重新框。
- 输入/输出计数来自扫描快照（最多落后 1 秒），是"当前库存"而不是累计吞吐。
- 分组产能台账是**估算积分**：按配方输出/输入 × 运行时间折算，不是真实输出总线计数；
  单方块读 `mLastRecipe`（反射），多方块只能拿输出/时长，输入侧统计会偏少。
- 存储机器目前只区分**量子箱 / 量子缸**（单方块）；超级箱/超级缸是多方块，走普通多方块记录。
- 分组图层/台账都只在客户端内存，退出游戏清零。
